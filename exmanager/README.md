# 実験データ整理（試用版）

Python標準ライブラリのみ使用します。Windows / TkinterのあるPythonで起動してください。

## PCの役割（将来の運用テスト用）

画面上部にPC名・固有IDの先頭8文字・役割を表示します。「このPCの設定」で名前と役割を変更できます。転送担当は直接コピー可能、操作・閲覧は履歴表示・セット作成・プレビューまで可能でコピー実行は無効です。操作・閲覧PCのプレビューにも現時点ではサーバー接続が必要です。

今回のPCは転送担当として登録済みです。他PCは初回起動時に新しいUUIDを発行し、操作・閲覧で開始します。WindowsのMachineGuidを設定ファイル選択に使い、MACアドレスには依存しません。設定はexmanager/.local/pc_*.jsonに保存し、Gitから除外します。このディレクトリはDropbox等の同期対象にせず、別PCへの配布にも含めないでください。同一Windowsイメージの複製でMachineGuidも同じになる環境は未対応です。設定を削除すると次回起動時に新しいIDになります。

役割変更は処理中にできません。変更後は再プレビューが必要です。転送したPCのID・名前は詳細履歴(manifests)に追記し、既存互換の17列CSVは維持します。

この段階は役割と識別のテスト実装です。遠隔依頼・バックグラウンド常駐・自動起動・PC間の進捗共有・履歴のDropbox統合・複数PCの排他制御は未実装です。役割設定は認証・アクセス制御の代わりにはなりません。コピーにはこのアプリとPCを起動しておく必要があり、同じ保存先へ複数PCから同時に転送しないでください。

## 起動と操作

「終了」ボタンまたはウィンドウ右上の×で、装置・コピー元区分・アップロード担当者・保存先実験・サンプル・Sample/Blankと各パスを、このPCの設定に保存します。次回起動時はCSVと保存先一覧を読み込んで選択を復元します。存在しなくなった候補は空欄になります。保存先の復元にはネットワーク接続が必要です。転送セット・元実験の複数選択は保存せず、コピーも自動開始しません。処理中は終了できず、設定保存に失敗した場合も画面を閉じずにエラーを表示します。強制終了時には保存されません。

```powershell
python exmanager/app.py
```

1. 装置・担当者CSVは起動時に自動読込します。パスを変更した場合は「装置・担当者CSVを再読み込み」。保存先解析ルートはプルダウンから選択します。選択すると保存先実験・サンプルの一覧を読み直します。「保存先一覧を読み込み」で手動更新もできます。「解析ルートCSVを閲覧・編集」で行を追加し、実験フォルダが並ぶ親フォルダのパスを入力して保存すると、選択候補に反映します。CSVはこのPCのexmanager/.local/AnalysisRoots.csvに保存します。初回は既定のサーバーと前回使用したルートを登録します。検証先もこのCSVに追加してください。登録済み転送セットの保存先は変わらないため、変更するセットは削除して再登録してください。
2. 装置、Recent_Data / Archived_Data、アップロード担当者を選択。「コピー元一覧を更新」。全装置をまとめて再取得する場合は「全装置のRecent_Dataを更新」、または「全装置のRecent_Data＋Archived_Dataを更新」を使います。装置CSVに登録された全装置を順番に取得し、進捗と更新日時・結果を画面下のログへ表示します。接続・保存に失敗したコピー元は前回の一覧を保持し、残りの装置を続けます。一括更新後は装置・コピー元を切り替えるだけで取得済み一覧を表示できます。
3. Ctrl / Shiftで元実験を複数選択し、保存先実験・サンプル・Sample / Blankを選択。「選択を転送セットに追加」。担当者・パスは追加時点の値で固定します。
4. 別の保存先についても同様に追加します。セット一覧の行を選んで削除できます。変更する場合は削除して再登録してください。
5. 「コピー予定作成」。名前・サイズ・保存先・採番と、重複候補の全内容を照合します。下の表に緑＝コピー予定、青＝重複スキップ予定、赤＝競合を表示します。登録表の件数は解析対象TDMSの確定結果に更新します。事前に件数の目安だけ知りたい場合は、任意で「簡易チェック」を使います。簡易チェックはサイズと先頭・中央・末尾各64KiBの比較で、コピー予定は作成しません。
   登録表の「名前の照合」列は、コピー元フォルダ名（`日付_時刻 装置条件_サンプル名`）の末尾のサンプル名と保存先サンプル名を比べた結果です（大文字・小文字は区別しません）。「不一致」「判定不可」の行は橙で表示し、追加時にも確認します。意図して別名で保存する場合もあるため、目安として使ってください。簡易チェックのログにも照合結果を出します。
6. 保存先・番号・警告と色分け表を確認し、「コピー開始」。解析用データのSHA-256照合とコピーを順次行います。登録セットを追加・削除した場合はコピー予定の再作成が必要です。上部の選択欄を変更しても登録済みセットは変わりません。

実験一覧には10kHz件数・100kHz件数・履歴件数・保存先数・最終保存日時を表示します。10kHz件数は実験フォルダ直下のEXSV/T直下、100kHz件数はEXZSV直下にあるTDMSファイル数です（拡張子の大文字・小文字は区別せず、下位フォルダは対象外）。対象フォルダがなければ0、読み取りエラー時は「取得不可」と表示します。「コピー元一覧を更新」で再集計します。同じ装置・コピー元を前回取得済みの場合は、前回の更新日時と一覧（フォルダ名・10k/100k件数）を確認画面に表示し、「前回の一覧を使う」（フォルダ走査を省略し、履歴列のみ最新CSVで表示）か「再取得して更新」を選べます。前回の一覧はこのPCのexmanager/.local/source_cache.jsonに装置・コピー元ごとに保存し、装置CSVのコピー元パスが変わった場合は確認なしで再取得します。装置・コピー元のプルダウンを切り替えたとき（起動時のCSV読込後も）は、前回の一覧があれば自動で表示し（フォルダ走査なし、履歴の色分けは最新CSV）、なければ一覧を空にして「① コピー元一覧を更新」を促します。保存先数は既存CSVの保存先実験・サンプル・10k/100kフォルダの組合せを重複除去して数えます（同じ場所への再実行は1か所、Sample/Blankは別扱い）。既存CSVにはサーバーのフルパスがないため、異なるサーバーで同名の場合は区別できません。
一覧をクリックすると、その実験のアップロード日時（uploaded_at）・実験日時（experiment_at）・保存先実験・サンプル・区分・実験担当者（operator_code）・アップロード担当者（uploader_code）を下の表にアップロード日時の新しい順で表示します。値が未記録の項目は空欄です。複数選択時は選択件数と、最後にクリックした選択行（キーボード操作時はフォーカス行）の履歴を表示します。

担当者は「アップロード担当者」に統合しました。既存CSVとの互換性のため17列の形式は維持し、新規履歴のoperator_codeとuploader_codeには同じアップロード担当者コードを保存します。過去の履歴は変更せず、画面にはuploader_codeを表示します。

進捗欄には処理段階、完了件数・割合、処理中のファイルと読み取り／コピー済みMiBを表示します。割合は各処理段階のファイル件数基準です。対象一覧の取得中は総数未確定のためアニメーション表示になります。ログ欄と実験一覧には縦・横スクロールバーがあります。ログを上へスクロールしている間は、新しい行が追加されても末尾に戻りません。

保存先の実験・サンプル・10k/100k/Tフォルダはcreate_folders.py等で事前に作成してください。履歴があっても別の保存先にコピーできます。セット登録順、セット内は実験フォルダ名の昇順で処理します。同じ保存先の番号は全セットで予約し、重複採番を防ぎます。同一転送の二重登録や別の元ファイルによる同じ保存パスへの衝突はプレビューでエラーになります。

一括実行中は「セット番号 / 全セット数」「実験番号 / 全実験数」とファイル処理進捗を表示します。競合・エラー発生時はその実験で停止し、後続実験は未実行とします。既にコピーしたファイルは残します。結果は試用版履歴と同じフォルダのbatches/*.csvへ実験ごとに記録し、完了済み実験の履歴はその都度保存します。再実行は再プレビューから行います。セット一覧はアプリ終了時に破棄されます。

## 保存仕様

- 両方の履歴CSV編集画面の「重複を確認・除去」で、全17列が完全一致する行を確認できます。現在の一覧の行番号と削除件数を表示し、確認後に各組の先頭1行を残します。日時だけが一致する行や列数が異なる行は除去しません。CSVへの反映は「保存」で行い、元ファイルの.bakを作成します。

- 10kHzの解析用は、EXSVの`D_`で始まるTXTとEXSV/Tの同名TDMSだけを対象にし、3桁以上の共通番号を付けます。`PM_`・`PML_`・`R_`などは解析用コピー・ペア不足警告の対象外です。raw dataにはこれらも含めて保存します。EXZSVのTDMS（`Z_`データを含む）は4桁以上の別番号です。数値を含む元ファイル名順で採番します。
- 保存先の最大番号の次を採番。同じ元ファイル名が保存先にあれば既存番号を使います。片方だけ削除したペアも同じ番号で補完します。
- 同じ内容の保存先ファイルは警告表示してスキップ。内容が異なる場合は全体の実行を止めます。上書き・元データ削除はしません。
- raw data/元実験フォルダ名へ全内容・空フォルダを保存します。既存ファイルは「既存（内容未検証）」としてスキップし、不足分だけコピーします。raw dataのSHA-256・既存内容の一致は確認しません。新規コピーではサイズとコピー中の元ファイル変更を確認します。詳細記録のraw dataのsha256列は空欄です。
- プレビュー後の元データ変更を再確認し、一時ファイルでコピー検証してから確定します。測定完了済みのフォルダを指定してください。
- 解析用の新規ファイルは事前に全体を読みません。コピー中にSHA-256を計算し、一時保存先を読み直して一致を確認した後に確定します。既存ファイルは元と保存先を各1回読んで照合し、一致すればスキップ、不一致なら停止します。サイズ・更新日時は処理開始時と各ファイルの処理直前に確認します。実行途中で競合が判明した場合、それまでに完了したコピーは残ります。
- 通常の転送処理では既存Uploader.csvへ書き込みません。暫定対応として、LabVIEW版CSVの編集画面に「Python版の不足履歴を取り込む」を追加しました。設定中のPython版CSVと全17列で比較し、未登録行を追加し、既存行も含めてuploaded_atの降順（新しい順）に並べます。既存行は上書き・削除せず、取り込み元内の重複も追加しません。内容を確認して「保存」を押すと反映されます。保存時は元の文字コード・改行・ヘッダー有無を維持し、.bakを作成します。
- Python版CSVの編集画面では「LabVIEW版の不足履歴を取り込む」で逆方向にも手動で取り込めます。全17列で比較して不足行を追加し、uploaded_atの降順に並べます。「保存」で反映し、.bakを作成します。同じuploaded_atの行同士の順序は両CSVで異なる場合があります。
- 試用版ログは既定でexmanager/logs/Uploader_python.csv（ヘッダー付き17列）。起動時および「装置・担当者CSVを再読み込み」で、既存CSVにだけある履歴を試用版CSVへ自動追加します。試用版だけの履歴も保持し、全17列一致で重複除去して日時の新しい順に統合します。変更がなければ書き換えません。同期件数・エラーはログ欄に表示します。
- 個別ファイルの保存先とSHA-256はlogs/manifestsへ保存。欠落警告がある場合は完了履歴へ登録しません。

## 検証と制限

まず既存結果を保持したまま、プレビューCSVの保存先ファイル名を確認してください。内容のSHA-256は実行時に計算し、完了後のmanifestsに保存します。既存の番号を再現するには保存先の事前状態をそろえます。全ファイルを削除した保存先では番号は1から再採番され、旧履歴の番号復元はしません。

試用版を複数起動して同時転送しないでください。CSV更新は一時ファイルから置換しますが、複数プロセスの履歴マージ排他には未対応です。旧ソフトによる書込中のCSV読込に失敗した場合は、書込完了後に再実行してください。旧ソフトとの併用では試用版の履歴パスを必ず別にします。

フォルダ名・大文字小文字を含めてTXTとTDMSが一致する構成を想定しています。長いUNCパスはWindows/Python/サーバーの設定により失敗する場合があり、実ネットワークでの検証が必要です。自動アーカイブ移動・削除は未実装です。

```powershell
python -m unittest discover -s exmanager -p "test_*.py" -v
```

簡易チェックとコピー予定作成では、保存先の10k/100kフォルダおよびそのTフォルダのstocked内にファイルがあると、退避ファイルの件数・パスと採番がずれる可能性をログと警告ダイアログに表示します。T/ANAL内にTDMSがある場合は「解析進行中」と表示します。どちらも下位フォルダを含めて確認します。空フォルダは通知しません。この検出による採番方法の変更やコピーの自動停止は行いません。
