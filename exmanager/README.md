# 実験データ整理（試用版）

Python標準ライブラリのみ使用します。Windows / TkinterのあるPythonで起動してください。

## PCの役割（将来の運用テスト用）

画面上部にPC名・固有IDの先頭8文字・役割を表示します。「このPCの設定」で名前と役割を変更できます。転送担当は直接コピー可能、操作・閲覧は履歴表示・セット作成・プレビューまで可能でコピー実行は無効です。操作・閲覧PCのプレビューにも現時点ではサーバー接続が必要です。

今回のPCは転送担当として登録済みです。他PCは初回起動時に新しいUUIDを発行し、操作・閲覧で開始します。WindowsのMachineGuidを設定ファイル選択に使い、MACアドレスには依存しません。設定はexmanager/.local/pc_*.jsonに保存し、Gitから除外します。このディレクトリはDropbox等の同期対象にせず、別PCへの配布にも含めないでください。同一Windowsイメージの複製でMachineGuidも同じになる環境は未対応です。設定を削除すると次回起動時に新しいIDになります。

役割変更は処理中にできません。変更後は再プレビューが必要です。転送したPCのID・名前は詳細履歴(manifests)に追記し、既存互換の17列CSVは維持します。

この段階は役割と識別のテスト実装です。遠隔依頼・バックグラウンド常駐・自動起動・PC間の進捗共有・履歴のDropbox統合・複数PCの排他制御は未実装です。役割設定は認証・アクセス制御の代わりにはなりません。コピーにはこのアプリとPCを起動しておく必要があり、同じ保存先へ複数PCから同時に転送しないでください。

## 起動と操作

「終了」ボタンまたはウィンドウ右上の×で、装置・コピー元区分・作業者・アップロード担当者・保存先実験・サンプル・Sample/Blankと各パスを、このPCの設定に保存します。次回起動時はCSVと保存先一覧を読み込んで選択を復元します。存在しなくなった候補は空欄になります。保存先の復元にはネットワーク接続が必要です。転送セット・元実験の複数選択は保存せず、コピーも自動開始しません。処理中は終了できず、設定保存に失敗した場合も画面を閉じずにエラーを表示します。強制終了時には保存されません。

```powershell
python exmanager/app.py
```

1. 装置・担当者CSVは起動時に自動読込します。パスを変更した場合は「装置・担当者CSVを再読み込み」。保存先解析ルートを確認し、「保存先一覧を読み込み」。検証時は保存先ルートを検証用フォルダに変更してください。
2. 装置、Recent_Data / Archived_Data、作業者、アップロード担当者を選択。「コピー元一覧を更新」。
3. Ctrl / Shiftで元実験を複数選択し、保存先実験・サンプル・Sample / Blankを選択。「選択を転送セットに追加」。担当者・パスは追加時点の値で固定します。
4. 別の保存先についても同様に追加します。セット一覧の行を選んで削除できます。変更する場合は削除して再登録してください。
5. 「全セットを確認（高速）」。名前・サイズ・更新日時・保存先と採番を確認し、内容は読みません。ネットワーク上の一覧取得に時間がかかる場合はあります。プレビューCSVはハッシュ未計算のためsha256列が空欄です。
6. 保存先・番号・警告を確認し、「一括コピー開始」。解析用データのSHA-256照合とコピーを順次行います。登録セットを追加・削除した場合は再プレビューが必要です。上部の選択欄を変更しても登録済みセットは変わりません。

実験一覧には履歴件数・保存先数・最終保存日時を表示します。保存先数は既存CSVの保存先実験・サンプル・10k/100kフォルダの組合せを重複除去して数えます（同じ場所への再実行は1か所、Sample/Blankは別扱い）。既存CSVにはサーバーのフルパスがないため、異なるサーバーで同名の場合は区別できません。
一覧をクリックすると、その実験の保存日時・保存先実験・サンプル・区分・作業者・アップロード担当者を下の表に新しい順で表示します。複数選択時は選択件数と、最後にクリックした選択行（キーボード操作時はフォーカス行）の履歴を表示します。緑色は従来どおり履歴あり／なしを表します。

進捗欄には処理段階、完了件数・割合、処理中のファイルと読み取り／コピー済みMiBを表示します。割合は各処理段階のファイル件数基準です。対象一覧の取得中は総数未確定のためアニメーション表示になります。ログ欄と実験一覧には縦・横スクロールバーがあります。ログを上へスクロールしている間は、新しい行が追加されても末尾に戻りません。

保存先の実験・サンプル・10k/100k/Tフォルダはcreate_folders.py等で事前に作成してください。履歴があっても別の保存先にコピーできます。セット登録順、セット内は実験フォルダ名の昇順で処理します。同じ保存先の番号は全セットで予約し、重複採番を防ぎます。同一転送の二重登録や別の元ファイルによる同じ保存パスへの衝突はプレビューでエラーになります。

一括実行中は「セット番号 / 全セット数」「実験番号 / 全実験数」とファイル処理進捗を表示します。競合・エラー発生時はその実験で停止し、後続実験は未実行とします。既にコピーしたファイルは残します。結果は試用版履歴と同じフォルダのbatches/*.csvへ実験ごとに記録し、完了済み実験の履歴はその都度保存します。再実行は再プレビューから行います。セット一覧はアプリ終了時に破棄されます。

## 保存仕様

- 10kHzの解析用は、EXSVの`D_`で始まるTXTとEXSV/Tの同名TDMSだけを対象にし、3桁以上の共通番号を付けます。`PM_`・`PML_`・`R_`などは解析用コピー・ペア不足警告の対象外です。raw dataにはこれらも含めて保存します。EXZSVのTDMS（`Z_`データを含む）は4桁以上の別番号です。数値を含む元ファイル名順で採番します。
- 保存先の最大番号の次を採番。同じ元ファイル名が保存先にあれば既存番号を使います。片方だけ削除したペアも同じ番号で補完します。
- 同じ内容の保存先ファイルは警告表示してスキップ。内容が異なる場合は全体の実行を止めます。上書き・元データ削除はしません。
- raw data/元実験フォルダ名へ全内容・空フォルダを保存します。既存ファイルは「既存（内容未検証）」としてスキップし、不足分だけコピーします。raw dataのSHA-256・既存内容の一致は確認しません。新規コピーではサイズとコピー中の元ファイル変更を確認します。詳細記録のraw dataのsha256列は空欄です。
- プレビュー後の元データ変更を再確認し、一時ファイルでコピー検証してから確定します。測定完了済みのフォルダを指定してください。
- 解析用の新規ファイルは事前に全体を読みません。コピー中にSHA-256を計算し、一時保存先を読み直して一致を確認した後に確定します。既存ファイルは元と保存先を各1回読んで照合し、一致すればスキップ、不一致なら停止します。サイズ・更新日時は処理開始時と各ファイルの処理直前に確認します。実行途中で競合が判明した場合、それまでに完了したコピーは残ります。
- 既存Uploader.csvは読取専用。試用版ログは既定でexmanager/logs/Uploader_python.csv（ヘッダー付き17列）。既存履歴を全17列一致で重複除去し、日時の新しい順に統合します。
- 個別ファイルの保存先とSHA-256はlogs/manifestsへ保存。欠落警告がある場合は完了履歴へ登録しません。

## 検証と制限

まず既存結果を保持したまま、プレビューCSVの保存先ファイル名を確認してください。内容のSHA-256は実行時に計算し、完了後のmanifestsに保存します。既存の番号を再現するには保存先の事前状態をそろえます。全ファイルを削除した保存先では番号は1から再採番され、旧履歴の番号復元はしません。

試用版を複数起動して同時転送しないでください。CSV更新は一時ファイルから置換しますが、複数プロセスの履歴マージ排他には未対応です。旧ソフトによる書込中のCSV読込に失敗した場合は、書込完了後に再実行してください。旧ソフトとの併用では試用版の履歴パスを必ず別にします。

フォルダ名・大文字小文字を含めてTXTとTDMSが一致する構成を想定しています。長いUNCパスはWindows/Python/サーバーの設定により失敗する場合があり、実ネットワークでの検証が必要です。自動アーカイブ移動・削除は未実装です。

```powershell
python -m unittest discover -s exmanager -p "test_*.py" -v
```
