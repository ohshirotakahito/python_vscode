# 特徴量抽出結果の履歴管理

新しい抽出は、サンプル・実行ごとに独立した結果を保存します。
選択した入力ファイルだけを処理し、過去の版への自動追記は行いません。
前回分と追加分を合わせた版が必要なら、両方の入力ファイルを選んで抽出してください。

```text
ML/data/features/rmb/                  # traditional
  サンプル名/
    YYYYMMDD_HHMMSS_ffffff_実行ID/     # 日本時間
      サンプル名_10k_Sample_ANAL_rmb.npy
      extraction_manifest.json
      extraction_runs.csv
      extraction_files.csv
```

tsfresh 用は `rmc`、Chronos は `rmd` に同じ構造で保存します。
各版の内部の結果ファイル名は従来と同じです。

## 画面での使い方

1. 特徴量抽出タブで手法・実験フォルダ・入力ファイルを選び、抽出を実行します。
   「条件メモ」は実験条件や用途の記録用です。計算設定自体を変更する欄ではありません。
2. 学習タブの「抽出結果の日時・条件を確認 / 使用する版を選択」を開きます。
3. サンプルごとに抽出日時・実験群・条件・入力ファイルを確認し、使用する版を選択します。
   実験群や条件IDで候補を絞り込めます。
4. 「保存して閉じる」で選択を反映し、通常通り学習を実行します。

「統計ヒストグラム」「抽出ファイル精査」でも、サンプルを選び、
「抽出結果の日時・条件を確認 / 使用する版を選択」から確認する版を指定できます。
サンプルごとに1つの版を選び、別の版に切り替えて再実行することで個別に比較します。
各タブの指定は独立して保持され、未指定のサンプルは最新の完了版を使います。
ヒストグラムは実行ごとのフォルダに保存され、`feature_inputs.json` に使用した版を記録します。
統計ヒストグラム・抽出ファイル精査の「実験フォルダ（出どころ）」を選ぶと、その実験の完了版がある
サンプルだけを表示し、実行時にはその実験の最新完了版を使います。
版を個別指定する場合も選択した実験内に限定します。実験を切り替えると、別実験の
版指定は解除されます。出どころ不明の旧形式は「すべて（旧形式を含む）」で選べます。
精査後に実験フォルダを変更した場合は、統計を読み込み直してから学習へ進みます。
「学習・評価」でも同じ出どころ選択を使えます。登録済みの組み合わせも選択した実験に
限定して版を確定し、該当版のないサンプルがあれば開始前にエラーを表示します。
出どころ変更時はファイル絞り込み条件を解除します。精査から引き継ぐ場合は出どころを
「すべて」に戻し、精査で使った版と条件を優先します。
「混合予測」でも出どころを選べます。純粋分子と混合サンプルの両方を絞り込み、
実行時にその実験の最新完了版を固定します。使用した版は予測結果フォルダの
`feature_inputs.json` に保存します。
混合予測の「混合サンプルのファイル絞り込みを設定」では、選択した混合サンプルの
ファイル統計を確認して条件を指定できます。「条件を保存して戻る」の後に予測を実行します。
条件は混合サンプルのみに適用し、純粋分子の学習には適用しません。使用した条件・ファイル・
件数は実行マニフェストの `mix_file_selection` に記録します。

混合予測の新しい結果は `mix_results/<手法>/<アルゴリズム>/<実行日時>_mix_<クラス>/`
に保存します。学習・評価の結果は従来の `results/` に保存し、④結果ブラウザは
学習・評価だけを表示します。過去の `results/` 内の混合予測も⑤混合予測から開けます。
Tkinter画面で予測完了時に、全体のグラフ・集計CSV・表示条件JSONを `views/` に保存します。
表示単位やファイルを変更した場合は「グラフ・集計を保存」で、その表示を追加保存できます。
精査画面のファイル一覧CSVには実行ID・抽出日時・実験・条件IDが含まれます。

未指定のサンプルは最新の正常完了版を使います。最新は抽出日時の順です。
異なる実験群・条件を混ぜたくない場合は、絞り込み後に各サンプルの版を指定してください。
絞り込み後の「この条件の最新」は、その時点の該当版に固定されます。
画面での版の指定はアプリを閉じるまで保持します。

学習を開始すると、バッチ内の全サンプルの版を確定します。
使用した版・入力ファイル・条件は学習結果の `run_manifest.json` の
`feature_inputs` に記録されます。途中で新しい抽出が増えても選択は変わりません。
tsfresh のキャッシュは、保存先・ファイルの更新情報・抽出パラメータ・対象イベントを区別します。

## 既存結果の互換性

従来の `data/features/<手法>/` 直下のファイルは、移動や再抽出なしで使用できます。
版の選択欄に「旧形式の保存結果（日時・条件不明）」として表示します。
新しい正常完了版がなければ旧形式を自動的に使い、新しい版があれば旧形式も明示的に選べます。
既存の22列の traditional 結果も、従来の読み込み互換処理を維持しています。
過去の履歴CSVと各版の履歴CSVは、抽出履歴画面でまとめて表示します。

旧形式の更新日時から抽出日時を推測したり、最後の履歴の条件を結果全体に割り当てたりはしません。
既存結果には複数実験の追記が含まれる可能性があるためです。
すでに上書きされた古い内容は復元できません。

## 記録内容と失敗時の扱い

`extraction_files.csv` には、元のサーバー（`server`）、共有フォルダ（`share`）、
実験（`ex`）、サンプル（`sample`）、ファイルナンバー（`file_number`）、
ファイル識別子（`file_key`）、元ファイルのパス（`anal_path`）、抽出日時（`extracted_at`）を保存します。
抽出日時は日本時間（`+09:00`）です。「抽出履歴」で実行を選ぶと、これらをファイルごとに確認できます。
既存の履歴もファイル識別子から番号を補完して表示します。番号を判別できない場合は空欄です。

`extraction_manifest.json` に抽出日時（`+09:00`）、実行ID、実験群、条件メモ、
波形の抽出設定、処理コードのSHA-256、ライブラリの版、入力ファイルのパス・サイズ・
更新日時、イベント数、結果ファイルの情報を保存します。
測定ID・Gap・元のファイル識別子など、イベントごとの情報は従来の結果ファイルに保持します。

中断・空の結果は `failed` として残し、自動選択には使いません。
一部の入力を読めなくても、有効な結果が保存されていれば完了版として使えます。
読めなかった入力と理由は `warnings` とログ・版の確認画面に表示します。
処理中は `running`、正常完了時のみ `complete` になります。
完了版の必須ファイルが消失・変更されている場合も候補から除外します。
入力ファイルの変更検出はサイズと更新日時による確認です。
同じ版の結果ファイルを手動で書き換えず、新しい抽出として保存してください。

## Python からの指定

```python
from common.feature_store import list_versions
from train_xgboost_tsfresh import run_analysis

versions = list_versions('rmc', 'サンプルA')
run_analysis(['サンプルA', 'サンプルB'], feature_versions={
    'サンプルA': versions[1]['run_id'],
    'サンプルB': 'legacy',
})
```

`feature_experiment='実験群'`、`feature_condition_id='条件ID'` を指定すると、
その条件に一致する版だけから選びます。指定した版や条件が見つからなければエラーにします。

中断した traditional / Chronos のチェックポイントを利用する場合は、同じ入力・条件で
`run_extraction(..., resume_run_ids={'サンプルA': '中断した実行ID'})` を指定します。
入力・条件・処理コードが変わっている場合や完了済みの版への再開は拒否します。
通常の再実行では新しい版を作ります。画面からは新しい版の作成を行います。

統計・混合予測・最適化版の学習も、新しい保存構造から最新の正常完了版を読み込めます。
過去の版の画面選択は Tkinter の学習タブで対応しています。
