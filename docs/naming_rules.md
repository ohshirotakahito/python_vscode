# 呼び名のルール（AXN・python_vscode 共通）

2026-11-23 決定。AXN（`D:\GitHub\AXN`）と python_vscode（実験ファイルDB・exmanager・Chip Atlas ほか）の**画面に出す呼び名**をそろえる。
経緯・未決の論点は [axn_database_roadmap.md](axn_database_roadmap.md)。

## 守ること

1. **変えるのは画面の表示だけ**。データの項目名・ファイル名・共有CSV の列名・LabVIEW が書く列名（`Operator`・`Device Code`・`EXID`・`Machine selection` など）は変えない。
   共有CSV（`D:\Qstatus\database\*.csv`）の列名を変えるときは、読む側（AXN）と同時に直す。
2. 新しい画面・列・メッセージは、下の表の「使う呼び名」で書く。「使わない呼び名」は新しく使わない。
3. どちらにも当てはまらない新しい言葉が必要になったら、先にこの表に足してから使う。

## 階層（2026-11-23 改定）

**プロジェクト → サンプル → 実験ID** の3段。例：プロジェクト `AXN_test` → サンプル `test01`・`test02`… → 各サンプルに装置ごとの測定（実験ID `20261121_0835 TOAN#1Pex3n2_test1` など）が複数。
「実験」は1回の測定（実験ID・実験設定・実験番号）の意味だけに使い、プロジェクトの意味では使わない。
当面は AXN の Ex Info（`machinedb\PLAN\ex_info.json`・`MeasurementLinks.jsonl`）で紐づけを整理し、整理後は実験ファイルDB で管理する。

## python_vscode の移行計画（2026-11-24 起案・AXN からの引き継ぎ）

AXN は v0.9.2.20（2026-11-23）で「プロジェクト → サンプル → 実験ID」に移った。Ex Info は整理が済むまでの暫定の置き場所で、
整理後は実験ファイルDB で管理する予定（AXN `docs/ex_info.md`）。python_vscode の画面を同じ階層・呼び名にそろえる。

### 現状（2026-11-24 に画面の文字列を数えた結果）

画面の文字列のうち、ID・日時・番号・設定・アプリ名以外で「実験」を含むもの：実験ファイルDB 約 70、実験データ整理 約 30、
Chip Atlas 約 30、Scoring 約 20、シグナル解析 約 10。意味は次の 3 つが混ざっているので、**機械的な置換はしない**。

| 今の書き方の例 | 意味 | 直し方 |
|---|---|---|
| 実験名、実験フォルダ、保存先実験、実験の責任者・説明、責任者（実験共通）、実験・サンプル | プロジェクト | **プロジェクト**・プロジェクト名・プロジェクトフォルダ・保存先プロジェクト |
| 元実験、コピー元実験、SQserver 実験一覧、{n}実験（転送セットの件数）、別実験、実験重複の可能性 | 1 回の測定（測定フォルダ） | 一覧・件数・フォルダを指すときは **実験ID**（例：コピー元の実験ID、SQserver 実験ID一覧、{n}件の実験ID）。動作や内容を指す「実験日時」「実験番号」「実験設定」「実験データ」はそのまま |
| 実験数 Ex#（Chip Atlas） | GPSET の件数 | そのまま（実験番号と同じ数え方）。補足に「実験ID の数」と書く |

ほかに残っている「使わない呼び名」：Chip Atlas の一覧・比較の列見出し `ChipID`（→ チップID。CSV の列名と書き出す CSV の見出しは変えない）、
実験データ整理の「担当者」「Operator」「試料」の残り（→ 測定者・転送者・サンプル）。

### 段階

1. **プロジェクトの意味の「実験」を直す**（画面だけ。2026-11-24 に段階2 とあわせて方針を了承）。実験ファイルDB → 実験データ整理 → Chip Atlas → シグナル解析・Scoring の順。
   アプリごとに 1 回の変更として版を上げる。公開CSV の列名（`実験名`・`転送先の実験名` など）・Ex Info の `experiment_folder`・
   内部の変数名は変えない。
2. **測定の意味の「実験」を実験ID にそろえる**（画面だけ）。とくに実験データ整理の「元実験」「コピー元実験」。
3. **残りの使わない呼び名**（`ChipID` の見出し、担当者・Operator・試料）。
4. **呼び名のテスト**：画面の文字列に「使わない呼び名」が新しく入らないよう、`shared` にテストを置く（データの列名・コメントは除外）。
5. **保存場所の呼び名を決める**（ロードマップ 4-14）：サーバー・共有・グループ・解析ルート・保存先の使い分け。決めてから直す。
6. **データの統一**（AXN と相談しながら）：Ex Info を実験ファイルDB へ移す形、サンプル台帳を `sample_key` でつなぐ（4-2）、
   メンバー表を人の正本にする（4-13。シグナル解析の解析者は 2026-11-23 にメンバー表からの選択に変更済み）。

## AXN でやること（1・3・4 は 2026-11-23 済み）

1. `axn/ui_catalog.py` の日本語訳を上の表に合わせる。主なもの:
   - `Sample Name`・`Sample name` → サンプル名、`Sample` → サンプル、`Sample Code` → サンプルコード、`Sample / Blank` → 計測区分
   - `Project`・`New project` など → プロジェクト（2026-11-23 改定。いったん「実験」にしたが、実験IDと混ざるため戻した）
   - `Device Code` → チップID、`Chip` → チップ
   - `Owner`・`Owner (project; …)` → 責任者、`Operator` → 測定者、`Recipe owner` → 計測条件の責任者
   - `Medium`・`Medium (sample)` → 溶媒
2. 装置の表示に `AXN#1` を出している所は、装置コード `AXN1` を出す（値の保存形式は変えない）。
3. 共有CSV・machinedb のファイル形式と列名は変えない。
4. AXN のテスト・版の決まりに従い、AXN のリポジトリでコミットして push する。
