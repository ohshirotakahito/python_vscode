# チップIDの修正（決まりに合わないIDを直す）

2026-11-18 開始。チップIDの決まりに合わないものを、段階を踏んで直す。
進み具合は共有フォルダの対応表 `D:\Qstatus\machinedb\PLAN\chip_aliases.json` に項目ごとに記録する（`shared/chip_aliases.py`）。
Chip Atlas の台帳の「ID修正」列に、旧名には「→ 新名（状態）」、新名には「旧名 …」を出す。

## 方針（ユーザーの決定、2026-11-18）

- **サーバーの実験データ以外は直す。** SQserver・解析サーバーの実験フォルダ、その中の結果ファイルの Device Code、
  ファイル名（`…_DV_<ID>-G044.txt`）、実験名（`…_CFD1061-Air`）は書き換えない。ここには旧名が残り続けるので、対応表は消さない。
- **一時的に旧名と新名を並べ、修正しながら、タイミングを見て統合する。** 一度に全部を書き換えない。
- **順番に進める。** 下の段階を 1 つずつ。段階が済むたびに対応表の `steps` に日時を記録する。
- CFD のIDは担当者に確認してから直す（段階 9）。

## IDの決まり

- SC: `SC` + ロット 2 桁 + `-` + ウェハー 4 桁 + `-` + チップ番号 2 桁（例 `SC25-2115-32`）。3501 チップのうち 3215 がこの形。
- 決まりに合わない SC は 48 個（2026-11-18 調べ）。36 個は機械的に直せる。12 個は人の判断が要る。

| 誤り | 数 | 例 |
|---|---|---|
| ロット番号の先頭に 0 | 15 | `SC080-4307-12` → `SC80-4307-12` |
| チップ番号が 1 桁 | 13 | `SC25-2117-9` → `SC25-2117-09` |
| 小文字の sc | 3 | `sc56-3602-06` → `SC56-3602-06` |
| 末尾の誤入力（` や _） | 2 | ``SC56-3603-31` `` → `SC56-3603-31` |
| ハイフンの重複 | 2 | `SC91-4419--07` → `SC91-4419-07` |
| ハイフン抜け | 1 | `SC914418-03` → `SC91-4418-03` |

このうち 6 個は、直した名前のチップが既にあり「統合」になる（同じチップとして履歴を 1 つにまとめる）:
`SC25-2115-9`、`SC68-3914-16_`、`SC77-4219--04`、`SC080-4307-06`、`SC080-4307-53`、`SC914418-03`。
