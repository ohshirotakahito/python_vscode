# ファイル管理アプリ

タブ順は「ファイルコピー → サンプル名一括変更・復元 → 名前変更・復元 → フォルダ作成」です。

ANAL・BNAL の整理（重複・退避・復帰）と Data 退避（解析済み T ⇄ T/stocked）は、シグナル解析アプリの「ANAL（サーバー）」「BNAL（サーバー）」へ移しました。どちらも「現状を調べる」で整理が必要なものを一覧にしてその場で整理し、足りない解析もそのページで実行します。「解析済み T → T/stocked…」で退避、「整理の履歴…」でこのアプリの記録（anal_logs・bnal_logs・t_stock_logs）も含めて元に戻せます。

BNAL用の退避・復帰（ANAL ⇄ stocked）は LabVIEW の BNAL が ANAL 直下をすべて解析するための手順でした。Python の BNAL（サーバー）は target ごとに B@@ の無い ANAL だけを解析するので不要です（ANAL/stocked に残った A@@ は「現状」で ANAL へ戻します）。以下の ANAL・BNAL・Data タブの説明は、過去の記録の読み方として残しています。

「BNAL 重複・退避・復帰整理」はBNAL進捗と同じrack_bnalsとrack_samplesの保存済み調査を参照します。BNAL@対象フォルダごとに件数・同番号候補数・基準ANAL件数（ANALとANAL/stockedの合計）・超過・調査日時を表示します。未計数・未調査は0件と区別し、未計数の対象は絞り込みを外して確認できます。検索欄の下のtargetリスト（CSV・複数可、初期フォルダはBNAL進捗と同じ）を選ぶと、そのCSVのtargetの対象フォルダだけに絞り込みます（「CSV選択を解除」で全target）。対象フォルダを1件選んで再調査し、新旧解析日の件数を比較して不要なグループまたはファイルを削除対象に指定します。超過のみでは内容重複とは断定しません。対象BNAL@直下とstocked直下のTDMSのみ操作し、子フォルダの内部や別BNAL@のファイルは操作しません。削除するBNALの.tdmsは、同じ日時・番号の結果フォルダ（B@@日時@…#番号）と一緒にそのBNAL@/.整理履歴に保管し、このPCのfilemanager/bnal_logsの操作履歴から元に戻せます。ANALと同様、実行前に解析処理を停止してください。整理後はそのサンプルのDBを自動更新します。

「BNAL用の退避・復帰（ANAL ⇄ stocked）」はBNALタブの操作です。BNAL@で欠けている番号だけをBNAL解析させ、終わったら戻すための操作で、BNALの件数を見ながら同じ画面で行えます。

- targetリスト（CSV）を選ぶと、表はそのCSVのtargetだけになり、「BNAL未完了・ANAL退避中のみ」で残りのあるtargetとANAL/stockedが残っているサンプルに絞り込みます（状態欄に「BNAL未完了 169/219（残り 50）」「ANAL/stocked n件（復帰待ち）」などを表示）。
- targetの行を1件選んで再調査すると、そのサンプルの共有のANAL・ANAL/stocked・CSVの全targetのBNAL@を直接読み、予定を作ります。
  - CSVの全target（基本配列・修飾配列）で済んでいる番号（0バイトでない.tdmsがある番号の共通部分。BNAL@がないtargetは済み番号なし）をCとします。
  - BNAL未完了のとき：ANAL直下のCの番号の.tdms＋.tdms_indexをANAL/stockedへ移し、欠番はANALに残します（以前の退避でstockedにある欠番はANALへ戻します）。ANALの結果フォルダは移動しません。各BNAL@のCにない番号（先行分）と0バイトの.tdms（書きかけ）は、同じ日時・番号の結果フォルダと一緒にBNAL@<target>/.整理履歴/操作IDへ移して削除します。削除は移動より先に実行します。
  - 全targetが完了したとき：同じ操作でANAL/stockedのファイルをANALへ復帰します。
  - BNAL@がないtarget、ANALにない番号のBNAL、ANALの同番号重複は警告として表示します（重複があっても実行はできます）。
- 確認画面で「BNAL・ANAL解析ソフトを停止しました」にチェックが必要です。実行後はそのサンプルのDBを自動更新して再調査します。履歴から元に戻すこともできます。
- 再調査の結果の上に、今の段階を色付きで表示します（黄＝未実行の予定あり・復帰できる／水色＝✔ 退避済み・BNAL解析待ち／緑＝✔ 完了）。実行が終わると、DB更新と再調査のあとに「実行完了」の画面で件数と現在の段階を知らせます。
- 実行履歴（JSON）の書き換えがウイルス対策ソフトなどで一瞬拒否された場合は、約20秒まで待って再試行します。それでも止まった場合は、再調査して同じ操作を実行すれば残りから続けられます。.tdmsと.tdms_indexが別々の場所に分かれていた場合は、付属ファイルを.tdmsのある側へ移します（Dataタブの退避・復帰も同様）。

100k Sample・Blankフォルダ直下のTDMSもサンプル名一括変更の対象です（フォルダ名・拡張子の大文字小文字は区別しません）。10k側のTDMSは従来どおりT直下を対象にします。予定表は「グループ」列と行の色でTXT・10kHz TDMS・100kHz TDMS・ANAL・BNAL・stocked・フォルダを区別します。グループ名でも検索できます。古い変更予定には追加対象がないため、アプリ再起動後に予定を再作成してください。旧履歴は当時の走査範囲で復元します。

サンプル名一括変更ではPS・BSフォルダ（大文字・小文字を区別しない）内を走査せず、内部のファイル名・フォルダ名は変更しません。親サンプルフォルダの改名に伴う上位パスの変更は発生します。旧履歴の復元は当時の走査範囲を維持します。PS・BS配下を含む古い変更予定は実行せず、予定の再作成を促します。

「サンプル名一括変更・復元」の変更予定・復元予定は、中央の表に順番・種類・グループ・変更前パス・変更後パスを表示します。300件ずつページを切り替え、検索は予定の全件を対象にします。色の凡例は表の下に表示します。パスは各操作時点のもので、親フォルダの名前変更は後の行で行います。取得中・取得失敗は予定が0件の場合と区別して表示します。ログへの予定一覧は先頭20件に制限し、全件は表で確認します。

「stockedを確認・取り出し」では、選択したサンプル・接尾辞配下のstockedを探し、その直下のファイルと親フォルダへの移動先を一覧表示します。Ctrl / Shiftで選んで移動すると、コピー予定を自動で再確認します。同名ファイルは上書きせずstockedに残します。コピー予定確認・コピー実行時にもstockedの残存ファイルをログに表示します。stocked内のファイルは通常のコピー対象には含みません。移動後も現在の対象・拡張子・BNAL選択に一致するものだけがコピー対象です。

リポジトリのルートから起動します。Tkinterが利用できるPython環境を使用してください。

```powershell
python filemanager/app.py
```

- **ファイルコピー**：コピー元サーバー、共有名、実験名、サンプル名を指定します。共有名の初期値は `analysis`。一覧ボタンはそれぞれサーバー直下の共有、共有直下の実験、実験直下のサンプルを自動で読み込みます。直接入力も可能です。サンプル一覧はCtrl / Shiftで複数選択できます。サンプル名の空欄は全サンプルです。
  周波数（10kHz / 100kHz）とSample / Blankを選ぶと接尾辞が決まります。初期値は `_10k_Sample` です。
  コピー対象は次の4種類を複数選択できます。拡張子は対象ごとに自動決定します。初期状態は `T/ANAL` の .tdms です。
  - 接尾辞フォルダ直下の `.txt`
  - `T` 直下の `.tdms`
  - `T/ANAL` 直下の `.tdms`（ANALは完全一致）
  - `T` 内の `BNAL@` で始まる各フォルダ直下の `.tdms`（末尾は任意）

  BNALは「すべて」（初期値）または「一覧から選択」を指定できます。「BNAL一覧から選択 / 更新」は現在のサンプル・周波数・区分に対応するT内を検索します。サンプル名とBNALフォルダ名の組ごとに複数選択できます。サンプル空欄の場合は全サンプルを検索します。コピー元やサンプル・周波数・区分の変更時はBNAL選択をクリアするため、一覧選択モードでは再選択してください。

  `create_folders.py` の標準構造を作り、選択した100k側などにもT・stocked・T/ANAL・T/stockedを補います。BNALのフォルダ名はコピー元と同じ名前にします。既存ファイルはスキップし、選択した場所がない場合はログに表示します。

  「コピー予定を確認」を押すと、画面下のログの先頭にコピー／スキップ件数、コピー予定サイズ、コピー元・先、対象サンプルをまとめて表示します。その下にはフォルダー単位で、各ファイルの状態・名前・サイズを一覧表示します。「既存・スキップ」はコピー先に同名ファイルがあり、上書きしない項目です。この確認ではフォルダ作成やコピーは行いません。確認後「コピー実行」で実行します。実行時に再検索するため、確認後に元・先の内容が変わると結果も変わります。

  同期先サーバーはコピー元以外の3台から選択します。共有名は自動入力／直接入力を切り替えられます。**実際の書き込み先はコピー元サーバー上の同期用共有**です。例：RackstationからQTserverへ渡す場合は `//Rackstation/RT_server/実験名/...` にコピーします。元ファイルは削除しません。同期そのものは既存の仕組みに任せ、同期完了の判断と同期先のanalysisへの移動は手動です。

  | 組み合わせ（順不同） | 自動入力する共有名 |
  |---|---|
  | Rackstation / QTserver | RT_server |
  | Rackstation / QDserver | RD_server |
  | Rackstation / QKserver | RK_server |
  | QDserver / QTserver | DT_server |
  | QDserver / QKserver | DK_server |
  | QTserver / QKserver | TK_server |

- **名前変更・復元**：対象フォルダを選択します。「置換」は配下を再帰的に処理し、「整形」は直下のファイルを既存の正規表現ルールで整形します。まず変更予定を表示し、ログを確認してから実行します。入力を変更した場合は再プレビューが必要です。件数制限の初期値は2件です（整形では走査するファイル数、置換では変更数）。
- **フォルダ作成**：サンプル名をカンマ区切りで入力すると、`create_folders.py` の構成を作成します。

コピー中は転送バイト数に基づく進捗率、処理件数、スキップ件数、経過時間、残り時間、終了予定時刻、平均転送速度を表示します。既存ファイルは転送量から除外します。終了見込みは平均速度に基づく概算で、ネットワーク状況により変わります。検索・確認中は割合を示さないバーを表示し、終了後は終了時刻と所要時間を表示します。同期完了までの時間は含みません。コピーは同じ保存先内の一時ファイルへ行い、完了後に正式名へ変更します。重複実行と処理中の通常終了を防止しています。「中断」ボタンで確認中・サンプル名変更中・復元中・新方式のコピー中に中止できます。従来の名前変更・CSV復元・フォルダ作成の実行中は停止対象外です。確認中は確認用プロセスを終了し、変更中は現在の1件と履歴保存を終えてから停止します。NAS応答待ち中は停止完了まで待つ場合があります。変更済みの分は残り、サンプル名変更の履歴から復元できます。停止後は予定を再確認してください。コピー済みファイルは残り、転送中の一時ファイルは削除します。

「サンプル名一括変更・復元」タブではサーバー、共有、実験、対象サンプルフォルダ、現サンプル名、新サンプル名を指定します。対象フォルダと内部のサンプル名が異なる場合も指定できます。たとえば対象フォルダ `L-aTNA-T-re`、現サンプル名 `L-aTNA-T`、新サンプル名 `L-aTNA-T-re` とすると内部の名前をそろえられます。英数字・ハイフンが直前直後にある別名は置換対象から除外します。プレビューの全件を確認してください。

走査対象はサンプルフォルダ自身、直下の `*_10k_Sample` / `*_100k_Sample` / `*_10k_Blank` / `*_100k_Blank` と、各測定フォルダ直下のtxt、stocked直下の全ファイル、T直下のtdms、T/stocked直下の全ファイル、T/ANAL配下の全フォルダ・全ファイル（ここだけ再帰）です。サンプルフォルダ直下にtxt・stocked・T・ANALがある構成も扱います。BNALおよびBNAL@で始まるフォルダは、その名前と直下のフォルダ名を確認・変更対象にします。BNAL直下のファイルや、その子フォルダの内部は走査しません。stockedのサブフォルダ内、raw data、その他のディレクトリは走査しません。親フォルダを変更すると、その配下にある対象外の項目も親の新しいパスに移りますが、対象外の項目自体の名前は変更しません。ファイル内容は読み込み・変更しません。確認中は走査先と件数を逐次ログに表示します。旧版の履歴も従来の対象範囲で復元できます。

「変更予定を表示」→ログを確認→「確認して変更を実行」の順で操作します。変更先の重複、リンク・ジャンクション、確認後の対象変更は実行を止めます。大文字小文字だけの変更には対応しません。子から親の順で名前を変更し、1件ごとにこのPCの `filemanager/rename_logs/samples/*.json` へ記録します。途中で失敗した場合もその履歴から実行済みの分を戻せます。

後日の復元は「履歴を選択・復元予定を表示」→ログを確認→「確認して復元を実行」です。履歴はアプリ終了後も残ります。対象を移動・削除した場合、変更先と同名の項目がある場合、ファイルの識別情報・サイズ・更新日時が変わった場合は復元を停止します。ファイル内容のバックアップ機能ではありません。履歴フォルダを保管してください（Gitには含まれません）。複数回変更した場合は新しい履歴から順に復元してください。

従来の「名前変更・復元」タブの履歴は `rename_logs` のCSVに保存されます。「履歴CSVから復元」で既存スクリプトの履歴も利用できます。既存処理と同様、例外によって途中終了した場合の自動ロールバックはありません。

ローカルの一時データを使う検証（Tkの画面を作成できる環境が必要）：

```powershell
python -m unittest discover -s filemanager -p test_app.py -v
```

「ANAL 重複・退避・復帰整理」タブは実験データベースの保存済みAnalysis_server調査（rack_samples）を読み取り専用で参照します。共有・実験・サンプル、ANAL件数、同番号候補数、退避件数、調査日時を表示し、検索できます。初期表示は同番号候補または退避がある対象のみです。チェックを外すと全対象を表示します。DBを切り替える場合は「DBを選択」後に読み込みます。

「選択サンプルのDBを更新」（ANAL・BNAL・Dataの各タブ、複数行可）で、選んだサンプルのTを共有から読み直し、実験データベースのAnalysis_server調査と同じ形で保存します（T・ANAL・stockedの件数と、全BNAL@のTDMS件数）。移動・削除・元に戻すを実行した後は、そのサンプルを自動で更新してから再調査します。実験データベースのアプリを開き直さなくても件数が最新になります（開いている場合は再読込してください）。実験データベースで同じ共有を調査中（DBに「実行中」と記録）の場合は、実行の確認画面と更新後のメッセージに警告を出します。警告だけで実行は止めません（データベースのアプリが途中で終了すると記録が残ることがあるため）。

対象を1件選び「選択した保存先を再調査」で、その場所のANAL直下とANAL/stocked直下のTDMSを取得します。「操作」を明示的に切り替えます。

- 退避の整理：青緑のstocked行を選択し「取り出し予定」→「取り出しを実行」で直上のANALへ戻します。同名衝突は停止します。
- 重複の整理：ファイル名の@@年月日で解析日グループを作り、新しい日を緑、古い日を紫で表示します。日付が取れないファイルは更新日を使います。同日内の別世代は分割しないので、ファイル名・更新日時で個別に判断してください。グループ表には総件数・ANAL/stocked件数・同番号候補件数・固有番号等の件数を表示します。新旧どちらを残すかは自動決定しません。「選択グループを削除対象に指定」または「選択ファイルの削除指定を切替」で対象を赤く表示し、「削除を実行」で確認画面に進みます。グループ指定は固有番号も含めたグループ全体が対象です。確認画面には整理後に残らない番号も表示します。


同番号はDBと同じくファイル末尾の#番号で判定する候補であり、内容・解析条件の一致は保証しません。解析を停止してから実行してください。削除対象はANAL/.整理履歴/操作IDへ移して復元可能な状態で保管します。stockedへの取り出しと混同しない専用の保管場所です。番号は変更しません。

操作履歴はこのPCのfilemanager/anal_logsにJSONで保存し、途中停止時も完了分を記録します。「履歴から元に戻す」で取り出し・削除のどちらも逆方向の予定を確認して戻せます。自動ロールバックは行いません。同名衝突やサイズ・更新日時・SHA-256の変化があれば復元を停止します。操作履歴とANAL/.整理履歴の両方を保管してください。整理後のDB件数は自動変更せず、実験データベース側で対象を更新してください。実ファイルのテストは `python -m unittest filemanager.test_anal_manager` で実行できます。
