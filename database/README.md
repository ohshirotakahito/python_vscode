# 実験ファイル データベース

5台のサーバーにあるファイルの保存状況を、ローカルSQLiteに保存します。
「ファイル操作」タブで、コピー・サンプル名変更・名前変更・フォルダ作成もできます（もとのファイル管理アプリ。[下記](#ファイル操作タブもとのファイル管理アプリ)）。
Python標準ライブラリのみ使用します。GUIにはTkinterが必要です。

```powershell
python database/app.py
```

## 操作

1. 「保存先設定」で共有パスを設定します。Rackstation / QTserver / QDserver / QKserverは `\\サーバー名\analysis` が初期値です。SQserverは共有名が未確定のため空欄です。原本の共有を `SQserver | experiment | \\SQserver\共有名` の形で指定してください。複数共有は1行ずつ追加できます。解析用共有がanalysis以外なら変更してください。
2. 画面上部でサーバーと共有を選び、「Recent_Data を更新」「Archived_Data を更新」「Stocked_Data を更新」「この共有を更新」「この実験を更新」のいずれかを押します。5台を一括更新するボタンはありません。起動時の自動接続はありません。
3. サーバー・実験・サンプル・周波数・Sample/Blank・分類別の件数と容量を確認できます。検索欄は保存パスの部分一致です。容量はファイルの論理サイズで、サーバーのディスク使用量・空き容量ではありません。ディスクの状況は「保存先の状態」の「ボリューム使用量 / 全体」列で確認できます（共有が載っているディスク全体の値で、その共有を正常に更新したときに記録します。同じディスク上の共有は同じ値になります）。
   「ファイル一覧」で検索に一致する実ファイルの記録を500件ずつ表示し、選択したファイルのフルパスをコピーできます。
4. 「集計CSVを保存」は現在選択しているタブの検索結果を保存します。行をダブルクリックすると長い名前やBNAL内訳も詳細画面で確認・コピーできます。
5. 他PCへ渡すときは「配布用DBを保存」でスナップショットを作成し、このフォルダのPythonファイルとともに配布します。他PCで起動し「別のDBを開く」で表示できます。閲覧時はサーバー接続不要です。自動配布・PC間同期は行いません。

更新ボタンは常にこのアプリのローカル `inventory.sqlite3` を更新します。別のDBを閲覧中でも配布用DBを更新することはありません。一覧選択からの実験更新はローカルDB表示中のみ利用できます。

Analysis_server は、初回表示・DB再表示・グループ更新の完了時に、全グループの保存済み行を `D:\Qstatus\database\analysis_server_all.csv` に自動保存します（UTF-8 BOM付き）。検索条件には影響されません。「最終取得 UTC」は各行のデータ取得日時、「CSV出力日時 UTC」はCSVを出力した日時です。失敗・中止したグループには以前の取得結果が残る場合があります。CSVは書き込み完了後に置き換え、保存失敗時は画面に理由を表示します。Excelで開いていて置き換えられない場合は、閉じて「DBを再表示」で再保存してください。このパス自体のPC間同期は行いません。

## 台帳の共有（計測PC向け・1時間ごと）

`publish.py` が、保存済みDBから台帳を `D:\Qstatus\database\` に書き出します。計測PCはこのフォルダの同期から、アップロード後の進捗（解析着手・ANAL・BNAL）を確認できます。CSVはすべてUTF-8（BOM付き）で、書き終えてから置き換えます。

| ファイル | 中身 |
|---|---|
| `sq_experiments.csv` | SQserver 実験一覧（装置・元の名前・解析着手・TDMS数・区分） |
| `analysis_server_all.csv` | 解析サーバーのサンプルごとのANAL進捗（Analysis_serverタブと同じ） |
| `bnal_progress.csv` | BNAL進捗（サンプル台帳で対象、またはBNAL@がある、対象外でないサンプル）。SEQlist未設定のサンプルは実在するBNAL@だけを載せます |
| `ledger_status.csv` | 各台帳を書いた日時・PC・行数、走査の結果 |

- **手動**: 画面上部の「台帳の共有」→「今すぐ実行（走査＋書き出し）」または「書き出しのみ」。コマンドでは `python database/publish.py`（`--no-scan` で走査なし、`--full` で夜間と同じ走査）。手動実行は自動実行の有効・無効に関係なく動きます。
- **自動**: 「台帳の共有」で「タスクを登録」（タスク スケジューラに `Qstatus Ledger Publish` を毎時5分で登録）し、「1時間ごとの自動実行を有効にする」をオンにします。オフにするとタスクは起動しても何もしません。設定は `database/publish.json`（このPCだけ、Git管理外）。
- **走査の範囲**: 毎時は SQserver の Recent_Data と解析サーバー全グループ。`nightly_hour`（既定 3時）の実行では Archived_Data・Stocked_Data と、全実験の BNAL TDMS 数も確認します。
- **同時実行の防止**: この画面の更新ボタンと publish.py は同じロック（`logs/scan.lock`）を使い、走査は1つずつです。ほかの走査中に自動実行が来たら走査を省き、保存済みDBから書き出します。
- **記録**: ログは `logs/publish.log`、前回の結果は `logs/publish_status.json`。

## サーバー・実験ごとの更新と進捗

- **Recent_Data / Archived_Data / Stocked_Data を更新**: SQserverの保存先設定のうち、その段階（backup_01〜08 / data / data_stocked）の共有を順番に更新します。他サーバーは走査しません。
- **この共有を更新**: 選択した共有だけを更新します。
- **この実験を更新**: 相対パス欄で指定した実験だけを更新します。解析用は `実験名`、SQserverは `backup_AN1/実験フォルダ名` や `data/AN1/圧縮ファイル名.zip` のように、登録した共有からの相対パスを指定します。パスの階層は共有設定によって変わります。
- **一覧の選択実験を更新**: 「解析用4台」または「SQserver 実験一覧」でCtrl・Shiftを使って選択した実験を順番に更新します。解析用の同一実験をサンプル別に複数選択しても走査は1回です。
- 実験候補は現在のDBの表示結果から取得します。未登録の実験は相対パスを直接入力できます。候補のために全サーバーを走査することはありません。
- 更新状況タブは、待機中・実行中・完了・失敗・中止・未実行を表示します。実行中は現在のフォルダ、確認ファイル数・フォルダ数、経過秒を表示します。総ファイル数は事前走査しないため、ファイル単位のパーセントは表示しません。画面下には完了対象数／全対象数を表示します。
- 完了は緑、実行中は青、失敗は赤、中止は黄で表示します。通常一覧は交互の背景色です。横スクロールと行のダブルクリックで長い内容を確認できます。
- 更新履歴はDBに保存され、再起動・他PCへの書き出し後も確認できます（画面は最新1000件）。待機後に中止した未実行対象はそのセッション内で表示します。強制終了などで完了が記録されていない履歴は「実行中／終了未確認」と表示します。
- 実験単位の更新はその範囲だけを置き換え、他の実験の記録は保持します。共有全体の最終取得日時は変更せず、解析/SQ専用一覧ではその範囲を正常取得した日時を表示します。子の一部分だけを更新した親は「一部更新」と表示します。
- 指定した実験が存在しない・読み取れない場合は失敗として前回記録を保持します。実験フォルダそのものの削除をDBへ反映する場合は共有全体を更新してください。存在する実験内で削除されたファイルは、その実験の正常更新で反映されます。
- 「更新を中止」は実行中の対象を取り消し、待機中の対象を未実行にします。すでに完了した対象は更新済みのままです。ネットワーク応答待ち中は中止まで時間がかかる場合があります。

## 解析用4台タブ

共有直下を実験、その直下をサンプルとして、10k / 100k × Sample / Blankごとに表示します。

| 列 | 数える対象 |
|---|---|
| T TDMS | T直下の `.tdms` |
| Tと同階層stocked 全件 | 周波数・区分フォルダ直下のstockedの全ファイル |
| T/stocked 全件 | T/stocked直下の全ファイル |
| ANAL TDMS | T/ANAL直下の `.tdms` |
| ANAL/stocked 全件 | T/ANAL/stocked直下の全ファイル |
| BNALフォルダ数・TDMS合計 | T直下の `BNAL@*` フォルダ数と、それぞれの直下の `.tdms` 合計 |
| BNAL内訳 | 各BNALフォルダ名と直下TDMS数（空も0件） |
| raw dataパス | サンプル直下のraw dataフォルダ名を含む相対パス |

子孫フォルダを通常の件数へ重複加算しません。TDMSの拡張子は大文字小文字を区別しません。
フォルダなしは「未作成」、存在してファイルなしは0です。4つの周波数・区分の欠落も行で表示します。

## SQserverの設定・表示

「SQserver 実験一覧」では相対パスの先頭フォルダを別列に分けて表示します。実験直下の子フォルダ表示はEXSV・EXSVZに限定し、それぞれの直下とT直下のTDMS件数を表示します。圧縮ファイルの中身は読み込みません。

「保存先設定」でサーバーを選び、「フォルダを選んで追加」から実際のフォルダを選択できます。複数の保存先は繰り返し選択し、最後に「保存」を押します。SQserverの空欄の初期行は自動的に置き換わります。`backup_AN1`、`data`、`data_stocked` に加えて `data/AN1` や `data_stocked/AN1` も選択でき、種別はパスから設定されます。親フォルダとその子フォルダを重ねて登録しないでください。

`experiment` はルートまたは直下の `backup_*` / `Recent data` / `Recent_Data` / `data` / `data_stocked` を自動分類します。
Recent data内にbackup_*がある場合はbackup_*ごとに集計します。backup_*がサーバーの別々の共有なら、それぞれを保存先設定に登録してください。サーバー直下の共有を自動列挙する機能はありません。

実際の共有名で分類できない場合、保存先設定で以下の種別を指定します（パスは例です）。

```text
SQserver | sq_recent | \\SQserver\backup_AN1
SQserver | sq_data | \\SQserver\data
SQserver | sq_stocked | \\SQserver\data_stocked
```

- Recent data: backup_*直下の実験フォルダ名・数、各実験のEXSV直下とEXSV/T直下のTDMS数を別々に表示します。
- data: AN1・AN2…直下のフォルダ名・数と圧縮ファイル名・数を別々に表示します。
- data_stocked: AN1・AN2…直下の圧縮ファイル名・数を表示します。もし通常フォルダもあれば別件数で表示します。
- 空のANフォルダやbackup_*もグループ集計に残します。分類できない保存先は「分類未確定」または「対象コンテナなし・設定を確認」と表示します。
- ZIP・7z・RAR・tar.gz・tar.bz2・tar.xz・tar・tgz・gz・bz2・xz・lzhを圧縮ファイルとして数えます。展開や中身の読み込みは行いません。分割圧縮の `.001` 等は対象外です。

実験名は `20260930_1234 TOAN#1Pex3n0_実験名` の形式を解析します。日付時刻は `YYYYMMDD_HHMM`（秒付きも可、区切りは `_`・空白・ハイフン）、全角の＃や数字にも対応します。実験日時はファイル名の時刻のまま表示し、タイムゾーン変換しません。
TOは操作者、AN#1は装置、3は実験回数、0は繰り返し回数です。後続の名前がなければ「無名」、形式が合わなければ「形式不明」、日時だけ読めなければ「日時不明」と表示し、元の名前は必ず残します。
実際のSQserverのパス・名前の実例は未確認です。形式が異なる場合も記録は失われず、元の名前を確認できます。

専門タブの検索は表示項目の部分一致、全ファイル集計・ファイル一覧はパスの部分一致です。SQグループ集計の件数は、検索に一致したコンテナ全体の件数です。

## 記録と更新の意味

- ファイル本体は読み込まず、パス・拡張子・サイズ・更新日時（Unix epochのns）を記録します。全拡張子を対象にします。空フォルダもfoldersテーブルに記録します。
- 解析共有は「実験/サンプル/...」構造を想定します。`*_10k_Sample` 等の名前から周波数・区分を読み取り、stocked / raw data / ANAL / BNAL / T直下 / その他に分類します。T直下を未解析と断定しません。
- 「全ファイル集計」タブではSQserverの最上位フォルダを実験／最上位フォルダ欄に表示し、分類は実験原本とします。SQserver専用タブでは上記の構造別集計を表示します。
- 選択範囲の走査が成功した場合だけ、その範囲の記録を置き換えます。ファイル一覧の過去世代は蓄積せず、更新作業の履歴は保存します。
- 読み取り失敗・切断・中止はその対象の更新を破棄し、前回記録を残します。未取得の共有は件数0でも空と断定できません。最終取得・最終試行・状態を併せて確認してください。すでに正常終了した他対象の更新は残ります。
- シンボリックリンク・ジャンクション等の再解析ポイントは除外し、除外数を表示します。
- 更新中のサーバー側の変更を固定する機能はありません。表示は走査時点の観測結果です。ネットワーク応答待ち中は中止要求が即時反映されないことがあります。
- 同じファイルが複数サーバーにあれば別々に数えます。内容の重複判定やSQserver原本と解析ファイルとの対応付けは行いません。
- 設定から外した共有の過去の記録はDBに残り、最終取得日時とともに表示されます。更新対象は保存先設定内の行です。
- DBはローカルディスクで使用してください。複数アプリの読み取りに対応しますが、更新は1プロセスずつ行ってください。配布にはSQLite backup APIを使う保存ボタンを使用してください（稼働中のDB本体だけのコピーは避けます）。

## 他のアプリ用の共通API

DBの窓口は `shared/` にあります（`shared/catalog.py`：files/folders/sources/updates、`shared/rack_store.py`：rack_samples/rack_roots/rack_bnals）。
DBファイル自体は従来どおり `database/inventory.sqlite3` です。Plotting・Analyzer はこの窓口だけを使い、`database/` は import しません。
テーブルの列や意味を変えるときの取り決めは [shared/README.md](../shared/README.md) を参照してください。

```python
from shared.catalog import DEFAULT_DB, sources, summary, find_files
from shared.catalog import scan_source, update_history
from database.inventory_views import analysis_inventory, sq_inventory

status = sources(DEFAULT_DB)  # 共有ごとの状態、最終取得、件数、容量
groups = summary(DEFAULT_DB, search='実験名')
files = find_files(DEFAULT_DB, search='sample', limit=1000, offset=0)
# 次ページはoffset=1000。rootとrelative_pathからフルパスを組み立てます。
analysis = analysis_inventory(DEFAULT_DB, search='サンプル名')
sq_groups, sq_entries = sq_inventory(DEFAULT_DB)
updates = update_history(DEFAULT_DB)
# scan_source(source, scope='実験名') で共有内の指定範囲だけ更新できます。
# 専門APIの件数Noneはフォルダ欠落（SQグループ集計では未確定）。0は存在して0件。
```

読み出しAPIはSQLiteをread-onlyで開きます。ネットワークの実ファイルにはアクセスしません。
スキーマv2: `sources`（共有と取得状態）、`files`（ファイル一覧）、`folders`（フォルダ一覧）、`updates`（更新範囲・作業履歴）。
SQLiteの `PRAGMA user_version` は2です。起動時にローカルv1 DBへupdatesテーブルを追加し、既存の記録を保持します。読み取り用の旧v1 DBも表示できます。DB本体と個人設定はGit対象外です。
専門集計は既存のfiles/folders記録から算出します。sources.last_successと従来のsummary/find_filesのlast_successは共有全体の取得日時です。範囲別の日時・状態には専門APIとupdate_historyを利用してください。

## Recent_Dataの解析着手状況

上部の「Recent_Data 着手状況」で専用画面を開き、「現状を照合」を押します。
装置CSV（exmanagerと同じMachine_N.csv）のTmp_backupからbackup_01〜backup_08を選び、
各フォルダ直下の現存する実験フォルダを読み取ります。ファイル本体は読みません。
装置CSV、LabVIEW版・Python版履歴CSVは画面で選択できます。

exmanagerと同じく、装置コードと元実験フォルダ名が履歴に一致すれば「着手済み」とします。
backup別の現存数・着手済み数・未着手数・着手率と、実験別の履歴件数・最終日時・保存先を表示します。
「未着手のみ表示」で未着手フォルダを絞り込めます。
これはコピー履歴に基づく着手判定で、コピー全件完了や解析完了の判定ではありません。
装置設定がないbackupは「未設定」、フォルダや履歴が読めない場合は「確認不可」とし、未着手に含めません。
この照合は表示中のSQLite DBとは別に現在のSQserverとCSVを読みます。サーバー接続が必要です。
移動・圧縮・履歴CSVへの書き込みは行いません。

## Analysis_serverのBNAL@記録

Analysis_serverタブの更新では、各サンプルの `10k_Sample/T` を一覧取得した際に見つかった `BNAL@<target>` の名前を `rack_bnals` テーブルへ保存します。`T/stocked`・`T/ANAL/stocked` がある場合は、その直下のTDMS数も「T/stocked」「ANAL/stocked（退避中）」列に記録します（フォルダがあるときだけ1回ずつ読み取ります）。ANAL進捗は「（ANAL ＋ ANAL/stocked）÷（T直下 ＋ T/stocked）」です。ANAL直下の `#NNN` 番号の種類数（`anal_distinct`）も、同じ一覧取得から記録します。BNAL内訳を数えるときは、ファイル数と `#NNN` 番号の種類数の両方を保存します。名前はTの一覧取得から得るため、サーバーへのアクセスは増えません。

「BNAL内訳のTDMS数も取得（検索中の実験のみ）」はデフォルトでオンです。オンの状態で更新すると、検索欄に一致する実験だけ、各BNAL@フォルダ直下の `.tdms` を数えます（下位フォルダは対象外）。フォルダ1つにつきサーバーへ1回アクセスするため、BNAL@が多いサンプルでは時間がかかります。検索欄が空の場合は、全実験を数えてよいか確認します。

数えなかった更新では、前回のTDMS数と確認日時（`tdms_checked`）を残します。Tから消えたBNAL@と、共有から消えたサンプルの記録は削除します。`last_seen` は名前を最後に確認した日時です。

## BNAL進捗タブ

保存済みのAnalysis_server情報（`rack_samples` / `rack_bnals`）だけを読み、サーバーには接続しません。

1. ①で実験・サンプル（10k_Sample）を選びます。絞り込み欄で部分一致検索ができ、Ctrl / Shiftで複数選択できます。
2. ②でtargetリストCSVを選びます。既定のフォルダは `D:\Qstatus\machinedb\SEQlist` です。CSVはヘッダーなしの `名前,配列,長さ` で、1列目を `BNAL@<名前>` と照合します。複数選択した場合は和集合を期待targetとします。
3. 「進捗を表示」を押すと、上の表にグループ別と全体の集計を、下の表にサンプル × target × グループの明細を表示します。

- 結果は「全体マップ」と「明細」の2つのサブタブに表示します。
- 全体マップは、1行 ＝ 1サンプル、1列 ＝ 1targetのマス目です。どのサンプルを次に解析するかを判断するための図です。
  - マスの色：赤＝未着手、黄＝進行中（濃いほど進んでいる）、緑＝完了、紫＝超過、灰＝未計数・未確認。マスの文字は作業中の共有の略称です（例：QTa＝QTserver/analysis、QTb＝QTserver/backup。「＋」は複数の共有）。
  - マップ上部の「サーバー表示」で全体／各サーバーに切り替えられます。保存済み調査にあるサーバーごとに完了・進行中／超過・未計数／未確認・保存TDMS数・取得済み分の残りを表示します。target・共有数は共有ごとの実行を数えます。全体の完了・残りは各targetの最も進んだ共有を使い、保存TDMS合計は共有間の重複を含みます。未計数分の件数は合計に含めません。表示は選択中のサンプルとCSVのtargetが対象で、サーバーの稼働状態を監視するものではありません。
  - 右側には、完了したtarget数、残りTDMS数（バー）、注意を表示します。注意の「⚠」と左端の黄の帯は、先に片付けが必要なサンプルの印です（退避・混在・不足・未取得）。「差異」は参考表示で、帯は付けません。
  - 並び順は右上の「並び」で選びます。初期値は「サンプル名順」（実験名・サンプル名の昇順。KUHCC2の次がKUHCC10になるよう、数字は数値として比べます）です。「次に解析すべき順」は、残りTDMSが多い順、同じなら未着手targetが多い順、さらに同じなら完了に近い順で、上にあるサンプルほど次に解析すべき候補です。
  - サンプル名・完了数・残りTDMSの列幅は、表示する文字の長さに合わせて決めます。
  - 下端には、targetごとの平均完了率を表示します。マスにマウスを乗せると詳細を表示し、クリックすると明細タブの該当行へ移動します。
  - targetが多い場合は、マスを細くして全体の濃淡を表示します（名前はマウスで確認）。「派生（_N_ / _M_）を親targetにまとめる」にチェックを入れると、`hsa-miR-193a-5p_M_11` などの派生を親targetの列にまとめます。並び順の計算は、まとめる前の派生ごとの値を使います。
- 進捗は「BNAL@直下のTDMSファイル数 ÷ 同じ共有のANAL（直下 ＋ ANAL/stocked）のTDMSファイル数」です。BNALは、その共有にあるANALファイル1つにつき1つ作られるためです。ANALは共有ごとにコピーされているので、分母はBNAL@と同じ共有のものを使います。
  - グループ別の行はTDMSファイル数で集計します。全体の行は、targetごとに最も進んだ共有の割合（最大100%）を出し、その平均を「target換算」で表示します。共有によってANALの内容が違っても、全体の期待値が膨らまないようにするためです。
  - 「同じ#番号の重複」列は、BNAL内で同じ `#NNN` 番号を持つ余分なファイルの数です（再解析の残り、またはANALの世代混在）。参考表示で、進捗の計算には使いません。
- 警告欄（高さ固定・スクロール）には、サンプルごとに次の内容を表示します。いずれも進捗の計算には影響しません。
  - 共有ごとにANAL数が異なる
  - ANAL/stockedに退避中のファイルがある
  - ANAL（stocked含む）が「T直下 ＋ T/stocked」より少ない（ANAL不足。誤った場所への移動などの確認用）
  - ANALに同じ `#NNN` 番号のファイルがある（ANALの世代が混在している可能性）
- `T/ANAL/stocked` は、BNAL解析を途中から再開するためにANALの一部を一時的に退避するフォルダです。退避中のファイルがあるサンプルは、①の一覧に「ANAL/stocked 退避中 N」と表示し、警告欄にも共有と件数を表示します。件数はAnalysis_serverの更新時に、stockedフォルダがある場合だけ数えます。
- 「選択サンプルのANAL旧世代をANAL/oldへ…」は、ANALの#番号の重複（世代混在の疑い）が記録された選択サンプルが対象です。各共有のANALを読み取り、次のように整理します。
  - ファイル名の日時（`A@@YYYY_MMDD_HHMM_SS_…#NNN.tdms`）順に並べ、#番号が最小の番号に戻る所を世代の区切りとします。#21からの途中再開のように最小番号へ戻らないものは、同じ世代として扱います。
  - 最新の世代以外の `.tdms`、同じ名前の付属ファイル（`.tdms_index` など）、対応する結果フォルダ（`A@日時@…#NNN`）を、`ANAL/old` へ移動（名前変更）します。
  - 実行前に世代ごとの開始日時・件数・番号範囲を表示して確認します。`ANAL/old` に同じ名前があるものは移動しません。BNAL@は変更しません。
  - ANAL/oldとANAL/stockedは、ANALの件数にも世代の判定にも含めません。
- 「選択サンプルのANAL/stockedをANALへ戻す…」は、ANAL/stocked直下のファイル（`.tdms`・`.tdms_index` など）を、同じ共有内でANAL直下へ移動（名前変更）します。実行前に移動件数を表示して確認します。ANALに同じ名前のファイルがあるものは移動せず、上書きもしません。下位フォルダは対象外です。各ファイルの結果は `database/logs/anal_moves.csv`（世代整理と共通。操作の種類も記録します） に記録し、移動後にそのサンプルの件数を再取得してDBへ反映します。ローカルDBの表示中で、更新処理が動いていないときだけ実行できます。中断したBNALをどこから再開するかの判定は対象外です。
- どの共有にもないtargetは「未着手」です。分母には、サンプルのANAL数のうち最大のものを使います。
- 同じtargetが複数の共有にある場合は「複数サーバー」と表示します。全体の集計では1件として数え、進捗の大きい方を採用します。BNAL数がANAL数を超える場合は「超過」と表示し、集計ではANAL数を上限として数えます。
- BNAL@名を保存する前に走査した共有（BNAL@フォルダ数より保存済みの名前が少ない共有）がある場合は、警告を表示します。そのサンプルで見つからないtargetは「未確認（要更新）」と表示します。
- TDMS数が未計数のtargetは、着手済みですが進捗0として数え、件数を警告欄に表示します。
- 「CSVにないBNAL@（一覧外）も表示」にチェックを入れると、CSVにないフォルダも表示します。一覧外のフォルダは集計に含めません。
- 共有の対応表示は、Analysis_serverの7グループの解析ルートで行います。登録外のルートはパスのまま表示します。

BNAL進捗の明細には、配列種別・基本配列名・基本配列TDMS数・ANAL数との一致・基本配列との一致を表示します。末尾が `_N_数字` または `_M_数字` のtargetは修飾配列として扱い、同じ実験・サンプル・共有にある基本配列のTDMS数と比較します（基本配列がCSVの対象外でも比較します）。基本配列の未作成と未計数は区別して表示します。修飾配列の完了には、ANAL数との一致と基本配列との一致の両方が必要です。進捗の百分率は従来どおりANAL数を基準にします。超過は要確認として扱い、完了件数に含めません。

## ファイル操作タブ（もとのファイル管理アプリ）

ファイル管理アプリ（`filemanager/app.py`）はこのタブに統合しました。ランチャーからは起動しません。
コードは `database/fileops/`（画面 `panel.py`、処理 `jobs.py`、既存スクリプト `create_folders.py`・`transfer_copy.py`・`rename_replace.py`・`file_rename.py`・`sample_rename.py` など）にあります。
処理は `jobs.py --worker` を別プロセスで実行し、ログ・進捗・変更予定をタブ下部に表示します。
ファイル操作の処理中は Data_server・Analysis_server の更新と BNAL・ANAL 進捗からの移動を、更新中はファイル操作を実行できません（どちらも終わってから実行します）。処理中に画面を閉じることもできません。

子タブの順は「ファイルコピー → サンプル名一括変更・復元 → 名前変更・復元 → フォルダ作成」です。
ANAL・BNAL の整理（重複・退避・復帰）と Data 退避（解析済み T ⇄ T/stocked）は、シグナル解析アプリの「ANAL（サーバー）」「BNAL（サーバー）」にあります（「整理の履歴…」で元に戻せます）。

- **ファイルコピー**：コピー元サーバー、共有名（初期値 `analysis`）、実験名、サンプル名を指定します。一覧ボタンはサーバー直下の共有、共有直下の実験、実験直下のサンプルを読み込みます（直接入力も可。サンプルは Ctrl / Shift で複数選択、空欄は全サンプル）。
  周波数（10kHz / 100kHz）と Sample / Blank で接尾辞が決まります（初期値 `_10k_Sample`）。コピー対象は「接尾辞フォルダ直下の `.txt`」「`T` 直下の `.tdms`」「`T/ANAL` 直下の `.tdms`」「`T` 内の各 `BNAL@*` 直下の `.tdms`」から複数選べます（初期状態は `T/ANAL`）。BNAL は「すべて」か「一覧から選択」です。コピー元・サンプル・周波数・区分を変えると BNAL の選択はクリアされます。
  **実際の書き込み先はコピー元サーバー上の同期用共有**です（例：Rackstation → QTserver は `//Rackstation/RT_server/実験名/...`）。元ファイルは削除しません。同期完了の判断と同期先の analysis への移動は手動です。標準フォルダ構造を作り、T・stocked・T/ANAL・T/stocked を補います。既存ファイルはスキップします（上書きしません）。

  | 組み合わせ（順不同） | 自動入力する共有名 |
  |---|---|
  | Rackstation / QTserver | RT_server |
  | Rackstation / QDserver | RD_server |
  | Rackstation / QKserver | RK_server |
  | QDserver / QTserver | DT_server |
  | QDserver / QKserver | DK_server |
  | QTserver / QKserver | TK_server |

  「コピー予定を確認」はコピー／スキップ件数・予定サイズ・コピー元と先・ファイル一覧をログに出すだけで、何も変更しません。「stockedを確認・取り出し」は選んだサンプル・接尾辞配下の stocked 直下のファイルを一覧にし、選んだものを親フォルダへ移してからコピー予定を再確認します（同名は上書きせず stocked に残します）。stocked 内のファイルは通常のコピー対象に含みません。
  コピー中は転送バイト数による進捗率・件数・経過時間・残り時間・終了見込み・平均速度を表示します。コピーは同じ保存先内の一時ファイル（`.fileops-*.part`）へ行い、完了後に正式名へ変えます。
- **サンプル名一括変更・復元**：サーバー・共有・実験・対象サンプルフォルダ・現サンプル名・新サンプル名を指定します（例：対象フォルダ `L-aTNA-T-re`、現サンプル名 `L-aTNA-T`、新サンプル名 `L-aTNA-T-re`）。英数字・ハイフンが直前直後にある別名は置換しません。
  走査対象はサンプルフォルダ自身、直下の `*_10k_Sample` / `*_100k_Sample` / `*_10k_Blank` / `*_100k_Blank`、各測定フォルダ直下の txt、stocked 直下、100k Sample・Blank 直下の tdms、T 直下の tdms、T/stocked 直下、T/ANAL 配下（ここだけ再帰）、BNAL・BNAL@ の名前と直下のフォルダ名です。PS・BS フォルダ内、BNAL 内のファイル、raw data などは走査しません。ファイル内容は変更しません。
  「変更予定を表示」→ 予定表（300件ずつ・全件検索・グループ別の色）を確認 →「確認して変更を実行」の順です。子から親の順に変更し、1件ごとに履歴へ記録します。後日の復元は「履歴を選択・復元予定を表示」→「確認して復元を実行」です（対象が変わっていれば止めます）。複数回変更した場合は新しい履歴から順に戻してください。
- **名前変更・復元**：対象フォルダを選びます。「置換」は配下を再帰的に、「整形」は直下のファイルを正規表現ルールで整形します。変更予定を表示してから実行します（入力を変えたら再表示が必要）。件数制限の初期値は2件です。「履歴CSVから復元…」で元に戻せます。
- **フォルダ作成**：サンプル名をカンマ区切りで入力すると、`create_folders.py`（`shared/folder_layout.py`）の標準構成を作ります。未作成の実験フォルダは作成します。

「中断」は確認中・サンプル名変更中・復元中・コピー中に使えます（従来の名前変更・CSV復元・フォルダ作成の実行中は止められません）。変更済みの分は残り、履歴から戻せます。

### 記録（このPCの `database/file_logs/`・Git 管理外）
